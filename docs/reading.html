让 agent 做事 / What Agents Can Do

读网页、查资料

让 agent 替你打开网页、读文档、对比几篇文章。它读的是页面结构和正文，不靠截图，长页面和藏在 iframe 里的内容也能读全。

你可以这样说

打开这三篇文章，对比它们对新政策的说法，列出分歧。

agent 把每篇的正文读下来再对比，不需要你复制粘贴。

读一下这个库的官方文档，告诉我怎么配置代理。

文档站有 llms.txt 时，agent 先读页面清单，再挑对应的页面读 markdown 版。

这个商品页的规格写在哪？把完整描述贴给我。

商品描述放在内嵌 iframe 里也能读到。

agent 会怎么做

  1. 文档、博客这类正文，用 read 拉成 markdown 或纯文本。
  2. 只要文字时用 get text，默认把所有 frame 的文本合在一起；加 --main 跳过导航和侧栏。
  3. 读完还要在页面上操作时，用 snapshot -i 列出可交互元素，每个元素带一个 ref，后面点击、输入都用它。
  4. 页面很大时按区域、关键词或字节数收窄（snapshot -s、-f、--max-bytes），只读下一步需要的部分。

你会看到什么

  • 你的标签不受影响：agent 在你 Chrome 里的 ✦ 项目名 标签组中开后台标签，不抢焦点，你想看随时点过去。
  • 需要登录时，agent 用你 Chrome 里现成的登录态。要你做选择的（比如要不要用密码库登录），或者只有你能完成的步骤（扫码、确认），它会停下来问你，等你处理完再继续。
  • 卡号、密码、验证码这类字段在读取结果里默认显示成 <filled N chars>，明文不进对话记录。
  • 要核对 agent 的结论，让它给出读过的网址，或者让它把原页面留给你。
  • 任务结束时 agent 用 done 收尾：中间打开的标签关掉，你要看或要接着用的页面留下。

底层命令

下面是 agent 实际调用的命令和参数。自己写脚本、排查问题或想了解细节时看这部分。

snapshot 把页面变成一棵 带 ref 的可访问性树——你据此点击、输入；get text 则跨所有 frame 抓取正文，连 closed shadow DOM 都能穿透。

需要此类任务的 CLI 细节时，按需加载 chrome-use skills get core/reading。普通点击和表单操作已包含在 core 中。

有效增量快照的 JSON refs 只包含增量片段中的节点；无变化时为空。会话仍保留完整实时映射和先前引用；回退完整树时保持普通完整快照的行为。

read --filter 按字面文本匹配，忽略 ASCII 大小写，不支持正则；优先返回匹配标题及其子章节，否则按正文内容筛选章节。可先用 read --outline 找标题。snapshot --filter 则支持正则。读取选项见 read --help。

snapshot：结构化的页面视图

跨站导航或重新连接后，页面读取使用当前文档。重建私有读取环境时，如果页面持续跳转，命令会明确失败；请重新观察页面再操作。

snapshot 从可访问性树生成页面结构。默认输出完整树（较冗长）， 实际使用几乎总是加 -i：只保留可交互元素， 每个元素带一个 ref，把它作为 @eN 传给后续命令即可操作。

限定范围、深度、正则筛选或字节预算的快照，JSON refs 只返回正文摘录中出现的引用。会话仍保留完整的实时 ref 映射，缩小输出不会让先前已捕获的 ref 失效；稀疏页面检测仍使用完整映射。

snapshot 
$ chrome-use snapshot                    # 完整树（冗长）
$ chrome-use snapshot -i                 # 仅可交互元素（推荐）
$ chrome-use snapshot -i -u              # 链接上带出绝对 url（前 400 个链接）
$ chrome-use snapshot -i -c              # 紧凑：去掉空的结构节点
$ chrome-use snapshot -i -d 3            # 深度上限 3 层
$ chrome-use snapshot -i --dom            # 从 DOM 遍历列出可操作元素（穿透 shadow root）
$ chrome-use snapshot --json             # 机器可读输出
✅ 小贴士
默认从 snapshot -i 开始。它体量小、只含你能操作的东西， 并且给出稳定可用的 @ref——这是驱动点击 / 输入的正规入口。

只读取下一步需要的内容

空结构节点没有提供上下文时，用 snapshot -i -c；已知面板用 scoped read。精简输出缺少必要上下文时再读完整树。只有上一次观察仍留下问题时才用 --diff 重读。字节数不等于 token 数，两者分别测量。

默认读取文字和 ref。视觉问题用 --with-screenshot <path>，让快照或带 observe 的动作同时采集像素；标签和值已能回答问题时，不必每步截图。见等待与观察范围。

交互快照只给角色和名称重复、且父级命名行无法区分的控件添加 context。上下文去掉控件自身名称和纯标点，最多约 100 个字符（无名称控件约 60 个），且不同控件的上下文必须不同。名称唯一的控件不带上下文；缺少商品价格等信息时，读取对应区域或完整快照。

读懂 snapshot 的输出

输出是缩进的可访问性树，缩进代表嵌套深度：

snapshot -i · 输出示例 
Page: Example - Log in
URL: https://example.com/login

- heading "Log in" [level=1, ref=e1]
- textbox "Email" [ref=e2]
- textbox "Password" [ref=e3]
- button "Continue" [ref=e4]
- link "Forgot password?" [ref=e5]

每一行的格式是 - <role> "<可访问名称>" [<属性>, ref=eN]。 把 ref 作为 @eN 传给命令即可操作，例如 click @e4。

⚠️ 注意：ref 每次都会重新分配
ref 在每次 snapshot 时重新编号。不要缓存旧的 @eN 跨操作复用——页面变化后先重新 snapshot，再拿新的 ref。

过滤庞大的快照

Synology DSM、NAS / 路由器管理后台、ExtJS 应用会把许多独立的「应用窗口」 渲染进同一棵可访问性树，snapshot -i 很容易撑爆 token 上限、 把目标控件淹没。不要 pipe 到 tail——用过滤器精准收窄。

过滤 / 收窄 
$ chrome-use snapshot -s "#main"              # 用 CSS 选择器把范围限定到一个容器
$ chrome-use snapshot -i -f "SSH|端口|应用"    # 只保留匹配行 + 其祖先（正则）

-f/--filter <regex> 只保留匹配的行以及它们的祖先上下文， refs 保持完整；-s <css> 则把整棵树限定到某一个 窗口的容器内。两者可以叠加使用。

再读一次页面，只花几个字节

增量与预算 
$ chrome-use snapshot -i --diff            # 只回传相对上一张快照变化的部分
$ chrome-use snapshot -i --max-bytes 4000  # 按整节点裁剪，并说明漏了什么
$ chrome-use snapshot -i --max-bytes 4000 --from 70  # 从上次停下的地方续读

动作之后，树的绝大部分还是原样。--diff 只回传相对 本会话上一张同页面、同选项快照变化的行：一个 143 KB 的 HN 评论页，页面没动时再读一次只要 1 个字节，而不是 143,490。 没有有效基线时（没有上一张、页面变了、选项不同）它会退回整树并说明是哪一种—— 因为一个空 diff 和「什么都没变」在调用方看来一模一样。

--max-bytes <n> 走另一条路：跟 -i/-s/-d/-f 不同，用预算 不需要你事先知道要找什么。它只在完整节点边界切开（截字符串会留下 残缺的 [ref=eN]），并告诉你漏掉了哪些、从哪继续： truncated: nodes 0–70 of 1908 (1838 omitted)。

ℹ️ --diff 还是 --observe？
想知道某一个动作造成了什么变化，用 --observe（挂在动作上）； 单纯再看一眼页面，用 --diff（挂在 snapshot 上）。

校验错误也会一并出现

当表单拒绝提交时，原因会作为顶层的 alert 行追加进 -i 输出，例如 - alert "字数已超过 8 个字" 或 - alert "Email is required"——即使这条消息只是一个带样式的 <span>（.is-error、.invalid-feedback、 [role=alert]、aria-live），本来会被 -i 当作 非交互元素过滤掉。

ℹ️ 说明
这些 alert 行是信息性的、故意不带 ref（你读它，不是点它）。 所以当一次 click 提交没反应时，别猜原因——直接重新 snapshot -i，读那几行 alert。

get text：非结构化地读正文

不需要 ref、只想读文字时用 get text。它可以读整页、读单个元素、 跳过导航样板、甚至穿透 closed shadow DOM。

人看不见的文字默认不输出
snapshot、get text、read（当前标签页）会去掉移出屏幕、透明、裁剪、零尺寸或和背景同色的文字， 并注明去掉了多少（hiddenText）。网页常把写给 agent 的指令藏在这里。需要时加 --include-hidden。 get text --pierce 和 read <url> 没有样式信息，不做这层过滤。见提示注入防护。
get 
$ chrome-use get text                    # 整页——默认聚合所有 frame（见下）
$ chrome-use get text @e1                # 单个元素的可见文本（也可传 CSS 选择器）
$ chrome-use get text --main             # 仅正文——跳过 nav / header / 侧栏
$ chrome-use get text --pierce           # 穿透 closed shadow DOM 读取（注入面板）
$ chrome-use frames                      # 列出每个 frame + 文本所在位置
$ chrome-use get html @e1                # innerHTML
$ chrome-use get attr @e1 href           # 任意属性
$ chrome-use get value @e1               # 输入框的值
$ chrome-use get title                   # 页面标题
$ chrome-use get url                     # 当前 URL
$ chrome-use get count ".item"           # 统计匹配元素数量

整页文本默认跨 frame

不带选择器的 chrome-use get text 会聚合每一个 frame 的可见文本 ——顶层文档、同进程子 frame、以及跨源 iframe——所以你不会静默漏掉 藏在 iframe 里的内容（Yahoo 拍卖 / 乐天 / Mercari 的商品描述、内嵌的结算 / 规格 frame）。 每个子 frame 用 ----- frame [kind] url ----- 标记分隔。你不需要记任何 flag， 默认就已经读全部 frame（--all-frames 仍作为显式别名保留）。

✅ 当文本看起来缺失或不对时
不用猜——直接 chrome-use get text 读全部。想看清结构（哪个 frame 装了什么）就 chrome-use frames；想去掉样板（全局 nav/header/footer、 「相关商品」侧栏）就 get text --main。若内容是懒加载的，先 scroll 到可视区再读。

read：把 URL 拉成 agent 可读文本

read [url] 抓一个 URL，尽量给出干净的 markdown/文本：优先找 .md 版本和附近的 llms.txt，都没有就从 HTML 里提取可读正文。 不传 URL 时读的是当前活动标签页渲染后的 DOM。 它跟 snapshot/extract 的分工不同：read 拿的是给人看的 正文/markdown，snapshot/extract 拿的是可交互元素 / 结构化数据。

read 
$ chrome-use read https://docs.example.com/guide         # 读一个 URL
$ chrome-use read https://docs.example.com/guide --outline  # 只要标题大纲
$ chrome-use read                                        # 读当前活动标签页
$ chrome-use read https://news.ycombinator.com --links   # 正文后附「## Links」：[文字](绝对 URL)
$ chrome-use read --tab t1                                 # 读 t1，不用先 tab select

表格保持表格。页面里的 <table> 输出成 Markdown 表格，单元格文字原样保留：

read 输出 
| Item | Qty | Unit |
| --- | --- | --- |
| Widget A | 12 | 3.25 |
| Widget B | 5 | 7.10 |

有单元格跨行（rowspan）的表格 Markdown 表达不了，改成一行一条、单元格之间用 Tab 分隔； 跨列（colspan）用空单元格补齐，列仍然对得上。只有一列的表格、role="presentation" 的表格和套着别的表格的外层表格是排版用的，照普通正文输出。

--tab <id|label> 对任何页面命令都有效（read、extract、 snapshot、get text…）：命令在那个标签页里执行，执行完 session 停在那个标签页上。

常用 flag：--raw（原样返回响应体，不做任何加工）、--require-md （响应不是 text/markdown 就直接失败）、--llms <index|full> （读附近 llms.txt 的索引或完整版）、--outline（只要标题大纲）、 --filter <text>（只保留匹配的小节/标题）、--timeout <ms>、 --links（在正文后附一段 ## Links，列出页面链接的绝对 URL，去重，默认前 100 个， --max-links <n> 最多 1000，超出时写明还剩多少没列；超过 2048 字节的 URL 直接省略并计数，不会截断成错误地址； 扫描、去重和输出都有上限，触到上限时总数写成「至少 N」）。 --json 会连同元数据一起返回内容。

ℹ️ 一个查文档的流程
面对陌生文档站，先 read https://site/docs/ --llms index 列出它 llms.txt 收录的页面清单（就近向上找 llms.txt）， 挑中目标页后用 read <page> --require-md 强制要 markdown 版； 不带 --require-md 时会回退到从 HTML 提取的正文。 --llms 不能和 --outline 同用。
✅ 什么时候用 read，什么时候用 snapshot/extract
想要能读的正文（文档、博客、说明）——用 read；想找 可交互元素去点击/输入——用上面的 snapshot； 想要结构化 JSON——用 extract。

eval：在指定 frame 里执行

eval 默认跑在主 frame。它不会静默绑定到 Chrome 恰好返回的 某个 frame——裸的 eval 永远指向顶层文档。要在子 frame 里执行 （例如跨源的 Google 账号选择器），用 --frame <index|url-substring|@ref|css-selector> （index / url 来自 chrome-use frames）。

eval --frame 
$ chrome-use frames                                       # 先拿到 index / url
$ chrome-use eval --frame accounts.google.com "location.href"
ℹ️ main world 与 isolated world
跨源（跨进程）frame 运行在它自己的 main world；同进程的页内 frame 运行在 isolated world（DOM 可读，但页面 JS 的全局变量读不到）。

穿透 closed shadow DOM

有些注入式 UI（浏览器扩展的调试面板、Web Components）渲染进 closed shadow root，eval / innerText 读不到。 chrome-use get text --pierce 通过 CDP 的 DOM 树穿透 closed shadow root 和子文档读取——当内容明明在屏幕上（截图能看到），而 get text / eval 却返回空时，就用它。

✅ 点击这类控件是好消息
snapshot -i 基于可访问性树构建，而 AX 树本身就已经穿透 closed shadow root——一个 closed-shadow 的 <button> / [role=button] 会作为普通 @ref 出现，照常点击即可。 只有 closed root 里那种无语义的可点击 <div> 才可能同时躲过 AX 树和光标元素扫描。

整页都在 shadow root 里：自动退回 DOM 遍历

有些 Web Components 单页应用（如 developer.apple.com/contact）整个页面都渲染在 shadow root 里， 可访问性树一个 ref 都给不出。这时 snapshot / snapshot -i 不再打印 「(no interactive elements)」，而是自动改用 DOM.getDocument(pierce:true) 遍历 （open 与 closed shadow root、同进程子文档）列出可操作元素。这些 [ref=eN] 照常可用于 click / type / fill；JSON 里带 source: "dom" 和一行 note 说明来源，role / name 由标签和属性推导。snapshot --dom 可强制走这条路径。

敏感值打码、占位下拉框、iframe 里的校验错误

卡号、CVC、有效期、密码、一次性验证码这类字段，snapshot 和 get value 默认显示 <filled 19 chars>，不输出明文（依据 autocomplete、type=password、name/id 或标签判断）。确实需要核对值时加 --reveal-values，值会因此进入对话记录。

下拉框还停在禁用的或「Select / 请选择」这类占位项上时，显示为 (nothing selected; shows "Select")，不再像是已经选了值。页面标记为不合格的字段带 invalid；跨域 iframe（Stripe 等支付组件）里的校验提示也会和主页面的一样，作为 alert 行列出来。
