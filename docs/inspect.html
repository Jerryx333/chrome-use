chrome-use · 安装 · 已登录浏览器指南 · MCP · 选型

专项能力 / 前端调试

点选改代码（Inspect & Ask）

按快捷键 Alt+Shift+C，在页面上点一个元素，点加入对话。 元素会变成一张小卡片，放进这个标签页的侧边栏对话的输入框里；你接着问，发送后侧边栏里的 agent 拿到元素的选择器、位置、源码文件和截图，可以直接在这个标签页里操作它。 也可以切到终端会话（ocs）：写一句“这里改成什么样”，chrome-use 把这句话、元素的源码文件和行号、截图和样式， 通过 ocs 投给正在这个项目里干活的 Claude Code、Codex 或 Pi 会话，由它去改代码。 本地 dev server 和测试环境域名都能用，用的就是你已经登录的 Chrome。

开始使用

  1. 装好 chrome-use 和扩展。发到侧边栏对话需要扩展 0.5.69 及以上、CLI 1.5.223 及以上；发到终端会话需要扩展 0.5.57 及以上、CLI 1.5.214 及以上（路径范围、认领和仅本标签目标需要这两个版本）。
  2. 只有发到终端会话才需要 ocs，并在项目目录里开着一个 Claude Code、Codex 或 Pi 会话。没装 ocs 时，面板会给出安装命令，草稿不会丢。
  3. 在页面上按 Alt+Shift+C，或点工具栏图标里的 Inspect element。发到终端会话时，第一次使用会先问你是否启用。快捷键可以在 chrome://extensions/shortcuts 里改。
  4. 点元素。Shift+点击或拖一个框可以一次选多个（最多 8 个）；↑/↓ 在父子元素之间切换；P 暂停页面动画，方便选中会动的东西；Esc 退出。
  5. 弹出的面板顶部选发到哪里：侧边栏对话（默认）或终端会话（ocs），按网站记住。每个元素都可以单独写备注，或者在截图上画圈。 发到侧边栏对话时，可以先写一句问题（可选），按 Enter 或加入对话，见下一节； 发到终端会话时写修改要求，按 Enter 或 Send 发送。Shift+Enter 换行。

发到侧边栏对话（默认）

最直接的入口在侧边栏里：输入框下方工具栏最前面的选择元素按钮（准星图标）。点一下进入选择状态（按钮高亮，输入框上方提示“在页面上点一个元素 · Shift+点击可连选 · Esc 取消”）， 到页面上点元素：元素闪一下“已加入对话”，同时变成卡片出现在输入框里，选择自动结束，光标回到输入框。按住 Shift 可以连续选多个；再点一次按钮、点“取消”或按 Esc 退出。 截图和源码位置随后补上（卡片上的小圆点表示还在获取）；找到源码就显示 文件:行号，找不到什么都不显示。chrome:// 等页面上按钮不可用。 侧边栏里的点击不像快捷键那样带来 activeTab 授权，所以在扩展还不能访问的网站上第一次使用时，Chrome 会请你允许访问这个网站（只问一次）。

快捷键 Alt+Shift+C 打开的页面内面板也能发到侧边栏：

  • 加入对话会打开这个标签页自己的侧边栏（已经开着就直接加进去），元素变成输入框上方的卡片，面板里写的问题放进侧边栏的输入框。这一步不会发送任何东西，侧边栏里正在进行的对话也不受影响。
  • 可以多次点选，卡片累加，最多 8 个；同一个元素再点一次会替换原来的卡片。卡片上的 × 可以移除它。
  • 发送时，消息后面附上每个元素的上下文：选择器、页面地址、在哪个 iframe 或 Shadow DOM 里、一条从顶层页面就能找到它的 JavaScript 定位表达式、源码位置（如果找到了）、文字、HTML 片段和你的备注；截图作为图片附件（和你自己加的图片合计最多 5 张）。侧边栏的 agent 默认就在这个标签页里工作，可以直接用选择器读它、点它。会话记录里只显示你写的话，元素上下文折叠在“N 个点选的元素”下面。
  • 点选之后页面跳转或刷新，卡片仍然保留，标成“页面已变”；发出时会告诉 agent 这个元素可能已经不在了。关掉标签页，它的卡片也一起清除。
  • 能选中 open 模式 Shadow DOM 和同源 iframe 里的元素。跨站 iframe 只能整体选中，里面的内容读不到；closed 模式的 Shadow DOM 只能选到它的宿主元素。
  • 卡片只保存在扩展的会话存储里（浏览器关掉就没了），页面读不到；选取结束后页面上不留任何元素、属性或全局变量。

发到终端会话（ocs）

第一次在某个站点发送时，面板会问两件事：这个站点对应哪个项目目录，交给哪个会话。 候选项目来自本地 dev server 的进程目录、ocs 里会话的工作目录，以及哪个项目里真的存在页面标注的源码文件。 选一次就记住，之后同一站点直接发送。绑定可以在扩展设置的 Inspect & Ask 卡片里查看和解除。

页面怎么对上项目和会话

每个站点（可以再按路径细分）第一次选取时，面板会给出一张确认卡：“把这个站点的请求交给 某会话（所在目录）在 某项目”， 并列出依据：项目配置、本地 dev server、命中的源码文件数，以及测试环境部署的版本和你本地代码的关系。点 Hand over 设为站点默认， 之后不用再确认；点 Only this tab 只对当前标签页生效，刷新后恢复站点默认；Choose another 列出其他候选。 只有本机能核实的证据才会预选：项目配置、本地端口对应的进程目录，并且这个项目里正好只有一个运行中的会话。页面里的源码路径和版本号只用来排序。

项目配置：.chrome-use/inspect.json

测试环境最省事的办法：在仓库里提交一个配置，写明这个应用对应哪些域名，全组共享。

json 
{
  "version": 1,
  "sourceRoots": ["../../packages/ui"],
  "sites": [
    { "origins": ["https://test-admin.x.com", "http://localhost:5173"] },
    { "origins": ["https://*.preview.x.com"], "pathScope": "/admin" }
  ]
}
  • 文件所在的 .chrome-use 目录的上一级就是这个应用的根目录，monorepo 里可以每个应用放一份。
  • pathScope 按路径段匹配，/admin 包含 /admin/orders，不包含 /administrator；同一域名下多个应用时才需要写。
  • 支持一层子域名通配 https://*.preview.x.com：协议和端口必须一致，精确域名优先；确认时只绑定当前这个具体域名。
  • 文件顶层的 sourceRoots 可以列出共享包目录（相对应用根目录），会显示在确认卡上，确认后才算作这个页面的源码。
  • 只读取运行中会话所在的仓库里被 git 跟踪的配置；文件是符号链接、超过 64 KiB、版本不是 1 或有未知字段时会被拒绝，并在面板里说明。

在会话里认领站点

bash 
# run inside the agent session that should receive requests
$ chrome-use inspect link https://test-admin.x.com/
$ chrome-use inspect link https://apps.x.com/shop --path-scope /shop
$ chrome-use inspect list
$ chrome-use inspect unlink https://test-admin.x.com/

命令用 ocs 识别当前会话。站点或它重叠的路径已经交给别的会话时，不会覆盖，而是生成一条待确认的认领，面板下次打开时让你选择替换或保留； 确认之前请求仍然发给原来的会话。unlink 只能撤销当前会话自己的绑定。

绑定的会话退出、换了目录，或者本地端口改由另一个目录的 dev server 占用时，面板会重新弹出确认卡，不会悄悄改投。同一仓库的不同 worktree 当作不同项目。

源码定位：接入 code-inspector-plugin

元素要显示 文件:行号，项目需要在构建时给 DOM 加上位置标记。chrome-use 读取 code-inspector-plugin 注入的 data-insp-path 属性，支持 Vite、webpack、Rspack、esbuild、Turbopack，React、Vue、Svelte 等都可以。 面板发现页面没有标记时，会列出要改的地方，问你是否让你的 agent 来配置；也可以自己加：

vite 
// vite.config.ts
import { codeInspectorPlugin } from 'code-inspector-plugin';

export default defineConfig({
  plugins: [
    codeInspectorPlugin({ bundler: 'vite', pathType: 'relative', hotKeys: false }),
    // ...your other plugins
  ],
});
webpack 
// webpack.config.js / vue.config.js (configureWebpack)
const { codeInspectorPlugin } = require('code-inspector-plugin');

module.exports = {
  plugins: [codeInspectorPlugin({ bundler: 'webpack', pathType: 'relative', hotKeys: false })],
};

hotKeys: false 关掉插件自带的 Option/Alt+Shift 点选功能，否则按 Alt+Shift+C 时它也会响应。 chrome-use 只读取 data-insp-path 标记；如果你本来就在用插件自带的点选，可以保留，只是两者都会响应这个快捷键。

没有接插件时也能用：React 18 及以下的开发构建会读组件自带的源码位置，Vue 开发构建会读组件文件名； 都读不到时，消息会标明“没有源码位置”，带上选择器和文本，让 agent 自己搜。React 19 已经去掉了组件上的源码位置，所以 React 19 项目建议接插件。

实测 code-inspector-plugin 2.0.9 的构建产物里，标记是绝对路径（测试环境里就是 CI 机器上的路径）。chrome-use 只在你绑定的项目目录里按路径后缀找对应文件，找到的标为“按路径后缀匹配”，找不到的标为未核实，不会去项目目录以外查找。

测试环境

测试环境的页面也能点选，前提是测试构建里保留了位置标记。插件默认只在开发模式生效， 需要给测试构建显式打开。生产构建绝不能打开：开启后，能访问测试环境的人都能在页面里看到源码文件路径。

vite 
// Test builds only, never production. DEPLOY_ENV is whatever your CI sets.
const isTestBuild = process.env.DEPLOY_ENV === 'test';

codeInspectorPlugin({
  bundler: 'vite',
  pathType: 'relative',
  hotKeys: false,
  dev: () => process.env.NODE_ENV === 'development' || isTestBuild,
  server: isTestBuild ? 'close' : 'open',
});

// index.html of the test build: lets the agent compare revisions
<meta name="chrome-use-revision" content="%GIT_SHA%">
bash 
# a production build must contain no source marks
$ grep -rl "data-insp-path" dist/ && echo "FOUND: do not ship" || echo "clean"

测试环境跑的代码可能比你本地分支旧。页面带了 chrome-use-revision 时，消息会附上这个版本号， 并提醒 agent 先核对本地文件，行号只当参考。这个版本号也来自页面，只用来提示，不作为任何授权依据。

发送和状态

面板只显示 ocs 真实返回的结果，存储和唤醒分开说：

状态含义
Sentocs 已存储并唤醒了会话。只代表消息到了 agent 的队列，不代表代码已经改好。
Stored已存储，但会话没被唤醒（例如忙碌或拒绝）。agent 下次读收件箱时会看到，不要重发。
Unknown / Unconfirmedocs 可能已经存储，但回执丢了。不会自动重发；点 Check status 查询，确认没送出再开新批次。

完整内容（每个元素的 HTML、样式、截图）写在本机 ~/.chrome-use/inspect/ctx/<id>/，只有你自己能读，7 天后清理（之后只保留批次 ID 和结果，用来保证同一批不会发两次）； ocs 消息里只放摘要和这个文件的路径。没有 ocs 或不想投递时，Copy 会把同样的内容复制成 Markdown； Open in editor 会用 VS Code、Cursor、Windsurf 或 WebStorm 打开对应文件和行。

安全边界

  • 只在你按快捷键或点按钮时注入页面，不常驻任何页面，也不会弹出“正在调试此浏览器”的提示条。我们在 Chrome for Testing 155 上做过探测：页面用扩展 ID 请求它的几个资源（fetch、script、link 三种方式），结果与一个不存在的扩展没有观察到差异，40 次请求的耗时中位数也相同；relay 模式反检测基准列出的检查全部通过。这些是有限的观测，不是“无法被探测”的保证。选取期间加进页面的元素名每次随机生成，不带品牌标识；但选取界面本身在页面上是看得见的，选取时并不隐身。
  • 页面里的文本、HTML、组件名、源码路径都当作不可信数据，在消息里和你写的要求分开标注；它们不能决定投给哪个项目、哪个会话。
  • 输入框运行在扩展自己的 iframe 里，页面脚本读不到也改不了你写的内容。它凭一次性密钥向扩展证明身份，页面复制出来的输入框拿不到这个密钥。
  • 每次发送前重新检查输入框是否完整可见；被遮挡、半透明或被挪动时不会发送。这只能降低界面欺骗的风险，无法保证完全防住。
  • 截图只在页面就是当前可见标签、发送前后页面没变时才附上；否则丢弃截图并说明原因，不会替你切换标签。
  • 投递不会提高接收会话原有的权限，也不会替你启动 agent。

和同类工具的区别

code-inspector-plugin 的 AI 模式、React Grab、Agentation、MCP Pointer、Cursor 的 Design Mode 都能“点元素交给 AI”。 它们大多只支持本地 dev server，或者另起一个 agent 进程、经剪贴板或本地 MCP 交付。 Inspect & Ask 用的是你已登录的 Chrome，测试环境也能用；它把请求投给你已经在跑的那个会话，不另开进程，也不放宽权限。

故障排查

现象处理
按快捷键没反应在 chrome://extensions/shortcuts 确认快捷键没被别的扩展占用；chrome:// 页面和扩展商店页面无法点选。
面板提示 native host 未连接运行 chrome-use doctor；Copy 不依赖 host，仍然可用。
元素显示 no source location按上面的方法接入插件；测试环境要等下一次部署才生效。
提示面板被遮挡滚动页面让面板完整显示，或重新按快捷键。
