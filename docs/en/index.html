Getting Started

chrome-use

chrome-use is a browser tool for AI agents. Once it's installed, Claude Code, Codex, Cursor and other agents can read pages, collect data, fill in forms and publish posts in the Chrome you're already signed in to. You watch the tab and take over whenever a sign-in or verification comes up. Prefer not to open a terminal? Chat with a local agent right in Chrome's side panel.

Connect your agent in three steps

  1. Install chrome-use: one line, no npm, no tokens. On Windows use the PowerShell line in Install.
    bash 
    $ curl -fsSL https://raw.githubusercontent.com/leeguooooo/chrome-use/main/install.sh | sh
  2. Connect your Chrome: add the chrome-use extension from the Web Store, then register the local bridge once. Your agent then works in the Chrome you use every day, with no "Allow remote debugging?" prompt.
    bash 
    $ chrome-use extension install
$ chrome-use doctor   # self-check
  3. Give your agent the skill: the skill teaches it when and how to use chrome-use. Claude Code installs it from the plugin marketplace; other agents use npx skills.
    Claude Code 
    > /plugin marketplace add leeguooooo/plugins
> /plugin install chrome-use@leeguooooo-plugins
# Codex, Cursor and other agents
$ npx skills add leeguooooo/chrome-use -g

From there, tell your agent what you want done; you don't need to learn the commands. Clients that only speak MCP and can't run a shell (Claude Desktop, ChatGPT connectors) use the MCP server. For a guided first run, see Let Codex or Claude Code use your logged-in Chrome.

Ask your agent

A few common requests. The agent works in its own tab group in your Chrome and leaves your tabs alone.

📖 Read and research

Open these three articles, compare what they say about the new policy and list where they disagree.

The agent reads the page structure, not a screenshot, so long pages come through whole.
🧪 Collect data

Put the title, price and link of the first 50 items in this list into a CSV.

The agent handles paging and infinite scroll; popular sites have ready-made site adapters that return structured data in one step.
🖱️ Fill forms and work in admin panels

Update stock for these 20 products in the admin panel. Show me before you submit.

Clicks, typing, uploads and dropdowns are each checked against the page, not just the command's exit code.
🔒 Use your signed-in accounts

Check my GitHub notifications and tell me which PRs are waiting for my review.

Your Chrome's existing sessions are reused. At a sign-in or CAPTCHA the agent stops and hands it to you.
🧷 Test web apps

Go through the sign-up flow and screenshot every error and layout problem.

Works on local dev servers and staging, with screenshots, video and network interception.
🎯 Point at an element, change the code

(click a button on the page) Round these corners and match the header color.

The element's source location, screenshot and styles go to the agent already working in that project.

No terminal needed

💬 Side panel chat

Click the extension icon and chat with your local Codex, Claude Code, OpenCode or Pi in Chrome's side panel. It works in the current tab.
📱 Mobile remote

Away from your desk, keep the chat going from your phone: start a turn, follow progress, answer approvals, get notified when it's done.
⏰ Scheduled prompts

Schedule a prompt in the side panel, for example a summary of your dashboard every morning.

Why your agent should use your own Chrome

🔑 Already signed in

A fresh automation browser is signed in to nothing. chrome-use connects to the Chrome profile you use, cookies and sessions included.
🧩 Extension, not a debug port

A Web Store extension plus native messaging, no --remote-debugging-port, so no "Allow remote debugging?" prompt.
🎨 Several agents, no collisions

Each agent session gets its own colored tab group, so agents sharing one Chrome never fight over a tab.
🕵️ Stays out of your way

Agents work in background tabs without stealing focus or switching the window you're looking at. Click over whenever you want to watch.

Why not just use…

  • Playwright / Puppeteer / browser-use? They're built for writing automation code, and a fresh browser context has none of your sessions; they can also persist profiles or attach to an existing browser, so compare the actual connection path. chrome-use is built for agents and reuses the sessions you already have.
  • Claude's Chrome extension? Great, but Claude-only. chrome-use works for any agent, on the same real browser.
  • Raw --remote-debugging-port (CDP)? Chrome 136 restricts remote debugging of the default profile, and the details vary by version and connection mode. chrome-use uses a Web Store extension and native messaging, with no prompt.
ℹ️ What detector results mean
The documented CreepJS run reported 0% bot and 0% headless; nothing is injected into pages when driving your real Chrome, and the extension needs 12 permissions, no <all_urls>. This is a measurement in a particular environment, not a promise of invisibility or account safety; websites also weigh behavior, account history and network signals. Test conditions, --humanize and Cloudflare clearance reuse are in Stealth & Anti-detection.
