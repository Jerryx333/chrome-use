开始 / Getting Started

chrome-use

chrome-use 是给 AI agent 用的浏览器工具。装好之后，Claude Code、Codex、Cursor 这些 agent 就能在你已经登录的 Chrome 里替你看网页、抓数据、填表、发内容； 你在旁边看着，需要登录或验证时随时接手。不想开终端，也可以在 Chrome 侧栏里直接跟本机 agent 对话。

三步接上你的 agent

  1. 装 chrome-use：一行命令，不用 npm，不用 token。Windows 用 PowerShell 那一行，见安装。
    bash 
    $ curl -fsSL https://raw.githubusercontent.com/leeguooooo/chrome-use/main/install.sh | sh
  2. 连上你的 Chrome：从应用商店装 chrome-use 扩展，再注册一次本地桥。之后 agent 用的就是你平时那个 Chrome，不弹「Allow remote debugging?」。
    bash 
    $ chrome-use extension install
$ chrome-use doctor   # 自检
  3. 把技能交给 agent：agent 从技能里学会什么时候用 chrome-use、怎么用。Claude Code 走插件市场，其他 agent 用 npx skills。
    Claude Code 
    > /plugin marketplace add leeguooooo/plugins
> /plugin install chrome-use@leeguooooo-plugins
# Codex、Cursor 等其他 agent
$ npx skills add leeguooooo/chrome-use -g

装完就可以直接跟 agent 说要做什么，不用记命令。只能接 MCP、不能跑 shell 的客户端（Claude Desktop、ChatGPT connector）用 MCP 服务器。第一次想照着做一遍，看让 Codex 或 Claude Code 操作已登录 Chrome。

对 agent 这样说

下面是几种常见任务的说法。agent 会在你的 Chrome 里开一个自己的标签组去做，你的标签不受影响。

📖 读网页、查资料

打开这三篇文章，对比它们对新政策的说法，列出分歧。

agent 读的是页面结构，不是截图，长页面也读得全。
🧪 抓数据

把这个列表前 50 条的标题、价格和链接整理成 CSV。

翻页、滚动加载都由 agent 处理；常用网站有现成的站点适配器，一步拿到结构化数据。
🖱️ 填表、操作后台

在后台按这份表格把 20 个商品的库存改掉，提交前先给我看。

点击、输入、上传、下拉选择，每一步都核对页面结果，不只看命令有没有报错。
🔒 用你登录好的账号

看看我的 GitHub 通知里有哪些 PR 在等我 review。

直接复用你 Chrome 里的登录态。遇到登录或验证码，agent 会停下来让你处理。
🧷 测试网页

把注册流程走一遍，截图记下所有报错和样式问题。

本地 dev server、测试环境都能用，配合截图、录像和网络拦截。
🎯 点选元素改代码

（在页面上点一个按钮）这里改成圆角，颜色跟顶栏一致。

元素的源码位置、截图和样式一起交给正在这个项目里干活的 agent。

不开终端也能用

💬 侧栏对话

点扩展图标，在 Chrome 侧栏里跟本机的 Codex、Claude Code、OpenCode 或 Pi 对话，它直接操作当前标签页。
📱 手机遥控

离开电脑时用手机继续侧栏对话：发新任务、看进度、回答审批、收完成通知。
⏰ 定时任务

在侧栏里设好定时提示，比如每天早上让 agent 汇总一次后台数据。

为什么让 agent 用你自己的 Chrome

🔑 登录态现成

新开的自动化浏览器什么都没登录。chrome-use 连的是你正在用的 Chrome 配置，cookies 和登录态都是现成的。
🧩 走扩展，不开调试端口

商店扩展加原生消息，不走 --remote-debugging-port，不弹「Allow remote debugging?」。
🎨 多个 agent 各干各的

每个 agent 会话一个彩色标签组，几个 agent 共用一个 Chrome 也不会抢同一个标签。
🕵️ 不打扰你

agent 在后台标签里干活，不抢焦点、不切走你正在看的窗口；你想看随时点过去。

为什么不直接用……

  • Playwright / Puppeteer / browser-use？它们面向写自动化代码，新建的浏览器上下文没有你的登录态；也能持久化配置或连接已有浏览器，选型时比较具体连接方式。chrome-use 面向 agent，直接复用你已有的会话。
  • Claude in Chrome？它的扩展任何网站一次 fetch 就能认出来，chrome-use 的认不出。跨域 iframe 里的文字它只能看截图，chrome-use 直接读成结构化数据。用同一个模型做 botcheck（我们自己写的检测页）的四步操作，它被识破 5 项，chrome-use 1 项。实测对比
  • 裸 --remote-debugging-port（CDP）？Chrome 136 限制默认配置文件的远程调试，具体要求随版本和连接模式而变。chrome-use 走商店扩展和原生消息，不弹确认。
ℹ️ 检测结果能说明什么
我们自测 CreepJS 为 0% bot、0% headless；连真实 Chrome 时不注入 JS 补丁，扩展申请 15 个权限，不授予任何站点权限（没有 <all_urls>）。 这是特定环境的测量，不保证无法被检测或账号不会被封，网站还会看操作行为、账号历史和网络信号。 测试条件、--humanize 和 Cloudflare 复用见反检测与隐身。
